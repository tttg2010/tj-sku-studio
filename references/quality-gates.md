# v1.8 生产质量门

这份规则把“生成成功”与“可以交付”分开。自动检查只做筛查，商品主体、光影融合和平台可用性仍需查看原图与成图。

## 时间门

- 常规套图目标：20 分钟内得到经过视觉验收的可用整套图，而不只是下载结束或首批草稿；另记首次草稿耗时。未达标如实记录，不把“快但不能用”计为达标。这是待实测的内部目标，不是 SalpX 的保证。
- 单图修改目标：5 分钟内完成一次局部修改；若需要重建商品几何，转为新方案并重新评估。
- 同一槽位/概念最多初次提交加一次付费重试（共两次），不是“两次重试”。遇到 5xx、超时或已有任务 ID 时，先查询原任务或保留中间结果，不重复提交可能已计费的请求；换模型也不清零此计数。
- 记录开始时间、结束时间、模型、操作、输出数量、重试次数、失败原因和 QA 状态。

## 商品一致性门

逐项对照原图和所有相关参考图：

- 轮廓、比例、数量、颜色、材质和表面处理一致；
- Logo、印刷、缝线、开口、孔位、按钮、端口、配件和功能结构一致；
- 人物穿搭中衣服结构、长度、纹理、颜色和装饰一致；
- 不把用户未证明的材质、尺寸、性能、认证或包装信息写成卖点。

出现改色、变形、Logo 错误、数量变化或关键结构变化，状态为 `blocked`。优先切换到原始像素合成、局部蒙版或补充更清晰的源图；同一概念最多付费重试一次。

## 场景融合门

检查商品与场景是否共享同一透视、尺度、支撑面、光源方向、色温、景深和遮挡关系。边缘不能有白边、锯齿、抠图光晕或悬浮感；接触阴影、反射和局部遮挡必须与场景一致。

产品角度无法自然进入场景时，换场景或补拍视角，不用透视拉伸商品强行适配。

反光金属、白色材质的亮部不是透明；真孔洞和网眼也不能被填实。按 [production-v18.md](production-v18.md) 和 [original-pixel-compositing.md](original-pixel-compositing.md) 做独立保护区检查与黑/白/彩底预览。场景先检查视平线、支撑/悬挂点、光源与尺度，不能仅因“加了接触阴影”就通过。承重、穿戴、拉伸等受力状态需要相符实拍，不由未使用的抠图臆造。

## 套图门

每个图片槽位先写清楚买家问题、证据类型和后期排版位置。整套正常槽位两两比较，至少在以下五项中有三项不同：买家问题、镜头距离/角度、构图裁切、环境/互动、证据方式。字符串不同只是计划筛查；必须目视确认新增买家证据，不能改三个标签蒙混。A+ 必须新增细节、用途、对比、过程或品牌故事，不得只是主图换一句文案。

隐藏所有文案再看：画面本身能否表现卖点？没有细节、动作或使用证据时不得通过。主图/附图/A+ 数量、尺寸、文件逐项核销；A+ 策划不等于已生成。A/B 单变量变体单列，不顶替正常模块。

## 自动筛查

在本地运行：

```bash
python3 scripts/image_qa.py \
  --source /absolute/path/source.png \
  --output /absolute/path/generated-01.png \
  --output /absolute/path/generated-02.png \
  --report /absolute/path/qa-report.json
```

工具会检查文件能否解码、尺寸和比例、近重复图、基础颜色/边缘统计、SHA256，并在环境具备 OCR 时报告可识别文字。`automated_status=passed` 仅代表本地筛查，整体 `status` 仍为 `draft`。它不会把全图颜色相似度当成商品一致性证明，也不会把 OCR 空结果当成“没有文字”。报告中的 `manual_review_required` 仍需人工查看商品细节、场景融合、Logo 和平台规范。报告使用新文件名，不覆盖原图或旧记录。

套图必须按 [production-v18.md](production-v18.md) 使用 `production_guard.py plan/next/delivery`。具名复核附观察记录，不能靠填写全 true 假造验收；工具无法判断观察记录是否真实。旧 QA 报告与当前输出哈希不符时阻断。

## 交付状态

- `passed`：本地筛查通过，人工逐项复核通过，且没有未验证卖点。
- `draft`：图片可用于选方向或排版，仍有商品一致性、文字、卖点或平台规范需要确认。
- `blocked`：发现硬性身份错误、明显贴图/物理错误、近重复无法区分，或输入/输出不完整。

交付记录必须包含绝对路径、模型/profile、耗时、操作、保真方法、QA 状态和剩余风险。
