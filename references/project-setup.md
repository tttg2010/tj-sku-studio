# 项目目录引导与创建

## 先判断再动作

首次调用需要告知可新建项目目录，或使用已有目录。只询问“能做什么”不授权创建文件夹；不需要目录也能做方案策划。

- 用户给出了商品目录：默认复用，告诉用户绝对路径；不要再询问相同选择，不迁移原图。
- 用户给出单张图片：普通商品文件夹可继续作为原图/成图目录；临时剪贴板路径、系统临时目录不作为长期交付目录，提示建立或选择项目目录。
- 用户未给目录：问“需要新建项目目录，还是使用已有目录？”一次即可；选择期间可继续只读检查和策划。
- 用户说“直接创建”“帮我建项目目录”或明确授权自动安排：直接创建并验证，不额外确认同一件事。
- 未指定新建位置时，使用当前用户 Downloads 下的 `电商改图项目/YYYY-MM-DD-商品简称/`。先告知所选位置；商品简称不明确用 `未命名商品`，不为此阻塞。新项目重名时添加 `-02` 等后缀，不把“新建”静默变成复用旧项目。
- 若用户不想新建，则按指定输出位置处理，不反复提示。

## 创建命令

从 Skill 目录执行，参数替换为实际已选路径：

```bash
python3 scripts/salpx_image_client.py init-project --project-dir /absolute/path/to/project --product-name 商品01
```

`init-project` 不需要 Pillow、密钥或网络，只创建明确指定的项目目录和商品子目录。目录已存在时可以复用，报告 `project_created`/`product_created`；不删除、不覆盖、不移动已有文件，也不会复制原图。商品名只允许单个文件夹名称，不允许路径穿越。

创建完成后检查返回路径及其存在性，再告诉用户目录已经建立。失败则报告实际原因，不把计划中的路径当成成果。

## 文件组织

```text
项目目录/
├── 商品01/
│   ├── 原图.png
│   ├── 细节图.jpg
│   ├── generated-main-1.png
│   └── generated-aplus-01-1.png
├── 商品02/
│   └── ...
└── .salpx-prepared/
    └── salpx-prepared-.../
        ├── ref-01.jpg
        └── ref-02.png
```

- 每个商品的原图、细节图和成图处于同一商品目录。若已使用用户现有商品目录，保持原结构，不强制插入一层新目录。
- 新项目需要整理用户已指定的素材时，可以在该已授权工作流内**复制**素材到商品目录，保留原件；重名采用新文件名并核对复制结果。未明确授权不得移动或删除原图。
- 配置密钥仍在用户保护的 SalpX 配置位置，不放进项目、图片、日志或 ZIP。
- 压缩副本放项目级 `.salpx-prepared/`，不与原图混淆，也不作为成图交付。
- 批量运行前固定原始输入清单，按商品分组；排除 `generated-*`、`.salpx-prepared/`、`salpx-prepared-*` 和既有输出目录。一个请求只含本商品当前选定的最多 9 张参考，不能将所有子文件夹的图片堆进一个请求。
- 清理缓存或删除项目不是默认步骤；需要删除时单独确认目标和范围。
